Through the Keyhole

How an autoencoder learns to rebuild pictures from a handful of numbers, and what its bottleneck units end up standing for

Here are eight small pictures of a house in a landscape. Some have a door, windows or a chimney, some have a sun, a tree or a cloud, always in different combinations, and each picture is made of 256 gray pixels.

Suppose every picture has to pass through a channel that carries only six numbers, and on the other side a machine has to paint the picture again from those six numbers alone. Which six numbers would you send?

An autoencoder is a network that works out the answer by itself. Nobody tells it what a door or a cloud is; it receives the pictures, tries to copy them through the narrow channel, and corrects its connections a little each time the copy comes out wrong. At the end of this page we will open the channel and look at what each of its six units has learned to do.

01A picture is a list of numbers

To a network, a picture is a list. Each pixel holds a gray value between 0 (black) and 1 (white), and the 16 × 16 grid is read out into a single column of 256 numbers, the input vector x with entries x1 to x256. Press unroll and watch the grid become a vector.

The order in which the pixels are read is a convention. Reading row by row is the usual choice, but a snake that turns around at the end of each row, or a completely scrambled order, give lists that hold exactly the same information. Switch between the orders: the column changes its pattern while the picture stays the same. Whether the network cares about this order is a question we will return to once it has learned something.

02A funnel with a narrow neck

An autoencoder has two halves. The encoder connects all 256 input pixels to a small number of latent units, six to begin with. Latent unit j adds up its inputs, each multiplied by the weight of its connection:

z_j = b_j + Σ_i w_ij x_i

Here wij is the weight of the connection from pixel i to latent unit j, and bj is a bias. The latent units are linear: the activity of a unit is this weighted sum itself, and no threshold or saturating function (a sigmoid, for instance) is applied to it. The decoder fans out again, from the latent units to 256 output pixels, with weights vjm from latent unit j to output pixel m:

x̂_m = c_m + Σ_j v_jm z_j

The output x̂ (read "x hat") is the network's attempt at a copy of the picture. Input and output have the same size and the latent units sit in between, so the network has the shape of a funnel that narrows and widens again. The output units are linear as well, so the whole network is a chain of two linear maps; section 05 returns to what this choice implies. The six numbers z1 to z6 are the message that passes through the neck.

All weights start out random, so the latent units receive a meaningless mixture of the pixels and the output is a gray smudge with no resemblance to the input. Notice also that nothing in the wiring knows which pixels are neighbours: every pixel is connected to every latent unit in the same way.

03Learning from the difference

Learning starts with a comparison, pixel by pixel. The error em = x̂m − xm is positive where the copy is too bright and negative where it is too dark. Squaring the errors and adding them gives a single number, the loss L, which is zero only for a perfect copy.

Each weight is then nudged in the direction that makes the loss smaller. For a decoder weight the rule is short: vjm changes in proportion to the activity of latent unit j times the error at output pixel m. An encoder weight influences the error only through the decoder, so the errors are first sent backwards through the decoder weights, which gives every latent unit its share of the blame δj; the weight wij then changes in proportion to xi δj. This backward sweep is called backpropagation, and the learning rate η scales every change.

04Any order will do

Back to the order of the pixels. Below, two copies of the same network train side by side. The top one receives the pictures read row by row; the bottom one receives the same pictures in a scrambled order, and its starting weights are shuffled along with the pixels, so that the two start from the same point.

To the bottom network the pictures look like noise, and so do the copies it returns. Put the returned values back in place with the same key that scrambled them, and the picture appears. Compare the two loss curves while they run.

Every pixel is connected to every latent unit by its own weight, so the network has no notion of neighbourhood, and any consistent order is equivalent to any other: training follows exactly the same path, up to rounding in the last digits. The one requirement is bookkeeping at the output. The slot that carried pixel (row 4, column 9) on the way in must be read back as pixel (row 4, column 9) on the way out, otherwise a perfectly good copy comes out unreadable, as the switch for a different key shows.

05What the narrow neck learned

Each latent unit has two sides. Its receptive field is the set of its incoming weights w1j to w256,j, drawn as a 16 × 16 image: it shows which pixels drive the unit up (cyan) and which drive it down (orange). Its projective field is the set of its outgoing weights vj1 to vj,256, also drawn as an image: it shows what the unit paints onto the copy when it is active. The first card shows the output biases c, the picture the decoder paints when every unit is silent.

Without the penalty, the network only needs its latent units to span the right directions in the space of pictures, and any mixture of those directions reconstructs equally well. The loss cannot tell a unit that paints the sun from a unit that paints half a sun and half a door, so the units end up as arbitrary blends of the parts, and moving a single unit changes the whole copy at once.

The sparsity penalty adds a small cost μ Σ |vjm| for every outgoing weight that is not zero. After each step, every decoder weight is pulled a little towards zero, and the weights that are not needed end up exactly at zero. The cheapest way to paint a sun is now a unit that paints only the sun, and since the six parts of the scene never overlap on the canvas, each of them can be handed to a unit of its own. A small decay on the encoder weights (the λ in the code above) prevents the network from dodging the penalty by shrinking all of v while inflating all of z.

The receptive fields tell a different story from the projective fields. A unit that paints the sun only needs to detect whether a sun is present, and many patterns of incoming weights can do that job, so its receptive field can look quite unlike the part it paints.

Linear autoencoders and PCA. With linear units and no penalty, the best an autoencoder with k latent units can do is to reproduce each picture's projection, measured from the average picture, onto the first k principal components of the data set, the same subspace that principal component analysis finds (Baldi and Hornik, 1989). Gradient descent reaches that subspace, but it leaves the axes inside it undetermined, which is why the unpenalised fields look like blends.
A link to the brain. The idea that a sparsity constraint makes the parts of a scene appear has a long history in neuroscience. Olshausen and Field (1996) showed that asking for a sparse code of natural image patches yields basis functions that resemble the receptive fields of simple cells in primary visual cortex: localised, oriented and band-pass.

06The loop in one sentence

An autoencoder squeezes each picture through a narrow layer, compares the copy with the original, sends the difference backwards to find out which connection was responsible for which part of the error, and changes every connection a little in the direction that would have made the copy better. Repeated many times over the same eight pictures, this loop finds a compact code; with a small push towards sparsity, the units of that code come to stand for the parts from which the scene was built.
